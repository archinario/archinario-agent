# Агент на архитектурной доске: MCP и CLI

Агент может читать открытую схему, добавлять и редактировать блоки и связи,
переименовывать схему и удалять элементы. MCP и CLI используют общее Go-ядро.
Это инструменты для вашего агента: сама платформа не вызывает LLM и не требует
ресурсов для модели на VPS. PostgreSQL и личный кабинет не нужны.

## Подключить открытую доску

1. Откройте `/design`, выберите проект и схему.
2. «Файл → Агент на доске → Разрешить доступ к схеме».
3. Скопируйте JSON из поля «Данные подключения» в файл вне репозитория,
   например `/tmp/archinario-connection.json`, с правами `chmod 600`.
4. Закройте окно подключения и оставьте вкладку открытой. В шапке остаётся
   кнопка управления доступом. Ключ действует 30 минут и только для этой схемы.

Ключ даёт право изменения схемы: передавайте его только своему агенту, не публикуйте
в чатах, репозитории или скриншотах. Он не записывается в проект или localStorage.
«Отключить агента», переход к другой схеме, закрытие вкладки и перезапуск сервера
отзывают доступ. После истечения или сбоя подключитесь заново. Вкладка может работать в фоне; если браузер приостановит её,
новые запросы получат ошибку доступности вместо отложенного применения. сохранённые локально проекты от подключения не зависят.

## Собрать CLI

Из корня проекта, нужен Go1.26:

```sh
go build -o bin/archinario ./cmd/archinario
export ARCHINARIO_CONNECTION_FILE=/tmp/archinario-connection.json
./bin/archinario --help
./bin/archinario schema
./bin/archinario catalog --query database --limit 10
./bin/archinario read --section all
```

Можно вместо файла задать `ARCHINARIO_URL`, `ARCHINARIO_SESSION`,
`ARCHINARIO_TOKEN` в окружении процесса. Ключ не передаётся флагом командной строки.
URL — адрес сайта, например `http://127.0.0.1:3120` или `https://archinario.com`,
с которого создали подключение. HTTP разрешён только на loopback; редиректы
не пересылают ключ. Доступ на production появится только после публикации функции.

## Нарисовать схему

Сначала `read` и `catalog`. UUID создавайте через библиотеку UUID/`uuidgen`;
координаты дочерних блоков задаются относительно родителя. Пример файла patch.json:

```json
{
  "requestId": "orders-001",
  "expectedRevision": 1,
  "patch": {
    "upsertNodes": [
      {"id":"00000000-0000-4000-8000-000000000001","kind":"client","title":"Browser","x":100,"y":180},
      {"id":"00000000-0000-4000-8000-000000000002","kind":"service","title":"Orders API","technology":"Go","x":420,"y":180},
      {"id":"00000000-0000-4000-8000-000000000003","kind":"database","title":"Orders","technology":"PostgreSQL","x":740,"y":180}
    ],
    "upsertEdges": [
      {"id":"00000000-0000-4000-8000-000000000004","source":"00000000-0000-4000-8000-000000000001","target":"00000000-0000-4000-8000-000000000002","protocol":"HTTPS"},
      {"id":"00000000-0000-4000-8000-000000000005","source":"00000000-0000-4000-8000-000000000002","target":"00000000-0000-4000-8000-000000000003","protocol":"SQL"}
    ]
  }
}
```

`expectedRevision` берётся из последнего чтения, а не всегда равен 1.

```sh
./bin/archinario apply --file patch.json --dry-run
./bin/archinario apply --file patch.json
./bin/archinario status --request orders-001
```

CLI выводит успех только после подтверждённого сохранения в браузере. При таймауте
проверьте `status` и перечитайте схему. Для сетевого повтора используйте **тот же**
requestId и тот же пакет. Для новой правки — новый requestId и текущую ревизию.
Dry-run не резервирует requestId и не меняет документ. MCP использует тот же контракт.

Чтобы изменить блок, достаточно `{"id":"...","title":"New name"}` в upsertNodes.
Указанные поля сливаются с существующими, `null` удаляет необязательное поле.
Удаление — deleteNodeIds/deleteEdgeIds. При удалении контейнера дети сохраняют
мировые позиции, инцидентные связи удаляются. detailDiagramId доступен только
через обычный интерфейс. Неверный пакет не применяется частично.

Один пакет — одно Undo. Камера не прыгает: если объекты за экраном, нажмите
«Показать всю схему». Ручное редактирование, открытый диалог, конфликт localStorage
или перетаскивание приостанавливают применение агентских правок. При конфликте
перечитайте доску; автоматического перетирания ваших изменений нет.

## Подключить MCP

Сервер запускается локально через stdio. Команда — **абсолютный путь** к собранному
`agent/bin/archinario`, единственный аргумент — `mcp`. Окружение:

```json
{
  "mcpServers": {
    "archinario": {
      "command": "/absolute/path/archinario/agent/bin/archinario",
      "args": ["mcp"],
      "env": {"ARCHINARIO_CONNECTION_FILE": "/tmp/archinario-connection.json"}
    }
  }
}
```

Это распространённый JSON-формат настроек MCP-клиентов; точное место настройки
зависит от клиента. Новое подключение не добавляет инструменты в уже запущенную
сессию агента автоматически. Обновляйте connection-файл при новом подключении.

Инструменты:

| Инструмент | Назначение |
|---|---|
| archinario_list_components | Поиск типов/технологий, offset/limit |
| archinario_read_board | summary, nodes, edges или all; ревизия и доступность |
| archinario_apply_patch | Atomic patch; dryRun; ожидание подтверждения браузера |
| archinario_get_request | Проверить исход запроса после сбоя |

Правила для агента — [agent-context.md](agent-context.md).
MCP не публикует отдельный открытый HTTP endpoint: локальный адаптер обращается к
защищённому ключом HTTP API доски. Никакого доступа к другим браузерным вкладкам.

## Ограничения и проверка

Сессии живут в памяти одного Go-процесса: 32 одновременно, 100 квитанций на сессию,
30 минут доступа, 100 блоков/200 связей, пакет до 200 изменений. Обработанные пакеты
освобождают графы из памяти, остаются только хэши и квитанции. Несколько реплик
потребуют общего relay или sticky routing; текущий сервер один. Нет фонового
редактирования закрытой доски, облачного хранилища или совместной синхронизации.

```sh
go test ./...
```
